# AGENTS.md

SlipClip — Firefox + Chrome extension (`notion-clipper-source/`) + static site (`notion-clipper-site/`). No build step, no package.json, no dependencies.

## Commands

- Test extension: `cd notion-clipper-source && node test.mjs` (Node 18+, no deps; CI uses Node 22 — `.github/workflows/test.yml`, runs only when `notion-clipper-source/**` changes).
- Load extension (Firefox): `about:debugging#/runtime/this-firefox` → Load Temporary Add-on → pick `notion-clipper-source/manifest.json`. Chrome: `chrome://extensions` → Developer mode → Load unpacked → pick `notion-clipper-source/`.
- Preview site: `python -m http.server 4173 --directory notion-clipper-site` (mirrors `.claude/launch.json`).

## Extension architecture (`notion-clipper-source/`)

- `auth.js` — OAuth 2.1 with PKCE + dynamic client registration (RFC 7591, `token_endpoint_auth_method: "none"`) against `https://mcp.notion.com`. There is no backend/secret by design; do not "fix" auth by switching to Notion REST OAuth (it requires `client_secret`, unusable from a public client).
- `background.js` (MV3 module service worker) — owns auth, highlight capture and highlight sending (a right-click clips a highlight straight to Notion via `flushHighlights`; captures and sends share one `serial` queue so they never race on the stored list; a failed send stays queued, and the popup retries it with the `flush-highlights` message). The popup is destroyed when focus moves to the auth window, killing the token exchange mid-flight, so sign-in must stay in the background worker; the popup only messages it. Also strips the `Origin` header for `https://mcp.notion.com/*` via the DNR rule in `rules.json` — the MCP server's DNS-rebinding guard rejects browser origins.
- `extract.js` — runs inside the page via `scripting.executeScript`, which serializes the function source. `extractPage()` must not reference anything outside itself; Readability/turndown are injected as files first and exist only as globals.
- `mcp.js` — the MCP transport (`mcpTool`, `parseResults`, `normalizeId`, `unwrapPayload`, `errorText`), shared by the popup, the options page and the background worker. One session per tool call, on purpose. `mcpTool` gets its token by messaging the background worker; the worker cannot message itself, so it calls `useTokenSource(accessToken)` at startup.
- `clip.js` — the clip itself, shared by the popup and the background worker (Alt+Shift+C and the "Clip page to Notion" menu clip straight to the last destination). `flushHighlights` is here too: every highlight is a new page (page destination → a child page via `notion-create-pages`; database → a row), never appended content — do not bring `insert_content` back for highlights. The destination is `destinations.highlights` if the options page set one, else the popup's (`parent` / `parentType`, with a database's columns matched by `matchProperties`), so there is nothing to set up; with neither it throws `code: "no-destination"`, which the worker answers by opening the popup (`action.openPopup`), never a tab. `clipTo(tabId, …)` injects `extractPage`, builds the Markdown and creates the page with `notion-create-pages` (takes Markdown directly, not block JSON). A clip is always a new page inside a page or a new row in a database — there is no append mode; the popup has no "save as" and no paste-a-link field, so do not add either back. A database destination is fetched first (`readDestination`, cached per lifetime): its `collection://` id becomes the `data_source_id` parent — `database_id` is refused once a database has two sources — and `clipProperties` fills the title, url, tags (JSON array string; Notion rejects an option the column lacks, so `addTagsStatement` first runs `ALTER COLUMN … SET MULTI_SELECT(…)` via `notion-update-data-source` — SET replaces the list, so it restates every existing option with its color, from a fresh fetch, never the cache), and author / site / note / publication date when a column is named for them. Also the clip history (`clipped` in storage, last 500, keyed by `canonicalUrl`) behind the "Already clipped" notice.
- `popup.js` — the popup's UI, one pane with no tab state to track and no highlights list — highlights are clipped by right-click, so the popup only retries a failed send on open and links to Settings; do not bring the panel back. Owns the chosen destination (`dest`, persisted on pick as `parent` / `parentType` / `parentTitle` — the dropdown only displays it, so it must always have a row to show, see `renderPicker`), pinned destinations (`pinned` in storage), the tags chips (shown only for a database with a multi-select column), and title + note (folded in a `<details>`).
- `highlights.js` — the highlights store and every Notion-shaped decision, all pure and DOM-free: `canonicalUrl`, `addHighlight` (dedupes on the way in), `applyMapping`, `parseProperties` (reads the JSON in `notion-fetch`'s `<data-source-state>` — the real payload has no typed `CREATE TABLE`, only an all-`TEXT` SQLite block — and falls back to the typed `CREATE TABLE` that `notion-create-database` echoes), `matchProperties` (takes its own rules; clip.js passes the clip's), `parseFetchKind`, `highlightsMarkdown`, `flushPending`, `prune` (sent highlights are capped at 500; waiting ones never dropped). `flushPending` takes the writer as a callback, so a page destination changes only which MCP call goes inside it. A passage is capped at 2000 characters (Notion's rich-text limit) at capture; a column named `URL` or `id` must be written as `userDefined:URL`.
- `options.js` / `options.html` — an optional highlights-only destination, which is either a database (one row per passage, columns mapped) or a page (a new child page per highlight, nothing to map). `destinations.highlights.kind` discriminates; a config stored before pages were allowed has no `kind` and can only have been a database. The passage must map to the title column; Notion requires a title on every row. Saving a destination messages the worker to send anything already waiting.
- `vendor/` (`Readability.js`, `turndown.js`, `turndown-plugin-gfm.js`) — unmodified upstream release builds. Never edit; licenses live in `THIRD-PARTY-NOTICES.md`.
- `test.mjs` imports `auth.js`, `mcp.js`, `popup.js`, `clip.js`, `extract.js` and `highlights.js` under plain Node (no DOM). Keep those modules free of top-level `document`/`browser` access or tests break. `options.js` is not imported — it touches the DOM at top level.
- Two cross-browser traps, both already fixed — do not reintroduce them: Chrome does not support returning a promise from `runtime.onMessage` (crbug 1185241), so replies go through `sendResponse` with `return true`; and Firefox for Android has neither `contextMenus` nor `commands`, so both are registered behind a check — touching a missing namespace at top level throws and takes the worker, and with it sign-in, down with it.
- `notion-clipper-site/privacy.html` enumerates what is stored locally and what is sent to Notion. Anything new in `storage.local`, or any new call, belongs in both lists.
- Manifest is cross-browser MV3 (`background.service_worker` + `declarativeNetRequest`; Chrome ignores `browser_specific_settings.gecko`). The gecko block (`id: slipclip@todorx.dev`, `strict_min_version: 140.0`, `data_collection_permissions`) is load-bearing for Firefox.

## Site deploys (`.github/workflows/deploy.yml`)

- Pushes to `main` touching `notion-clipper-site/` publish to GitHub Pages; manual run via Actions tab. Requires repo setting Pages → Source: **GitHub Actions** (not branch deploy) + custom domain `slipclip.todorx.dev` with Enforce HTTPS.
- `notion-clipper-site/CNAME` must keep the hostname or redeploys drop the domain. `.nojekyll` is required for asset passthrough.
- Cloudflare fronts the site and serves CSS/JS with `max-age=14400` while HTML gets `max-age=600`. A stylesheet change therefore reaches nobody for four hours unless its URL changes, which is why `style.css` and `fonts.css` are linked with a `?v=YYYYMMDD` stamp (add a letter, e.g. `20261119b`, for a second change on the same day). **Bump that stamp in `index.html`, `privacy.html` and `404.html` whenever you edit one of those two files.** The home page is one screen with no script, by design: keep it that way. The `.woff2` files stay unversioned so the `preload` keeps matching the `@font-face` `src`.
- `dist/` (`*.xpi`, `web-ext-artifacts/`) is gitignored build output — never commit it.
